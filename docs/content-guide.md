# 執筆ガイド

部員が記事を書いて公開するまでの手順です。コードを書かなくても、このガイドの手順だけで記事を1本公開できます。

記事の仕様（front-matter の項目やカテゴリの決まり）は [article-spec.md](article-spec.md) §7 が正本です。このガイドは手順だけをまとめています。

## 全体の流れ

1. 作業ブランチを作る
2. テンプレートをコピーして記事を書く
3. 手元で表示を確認する
4. プルリクエスト（PR）を出す
5. レビューで1件以上の承認を得る
6. マージされると自動でサイトに公開される

## 1. 作業ブランチを作る

- ブランチ名は `content/<記事のスラッグ>` にします（例: `content/2026-11-01-limit-intro`）
- GitHub の Web 画面だけで作業する場合は、ファイルの追加画面からでも構いません

## 2. 記事を書く

### ファイルを作る

`src/content/articles/_template.md` をコピーし、名前を変えます。

- ファイル名 = そのまま記事の URL になります（`/articles/<ファイル名>`）
- 形式: `YYYY-MM-DD-<英小文字とハイフンの名前>.md`（例: `2026-11-01-limit-intro.md`）

### front-matter を書く

ファイル先頭の `---` で囲まれた部分です。項目の意味は次のとおりです。

| 項目 | 書き方 |
|---|---|
| `title` | 記事タイトル |
| `date` | 公開日（`YYYY-MM-DD`） |
| `author.department` | 自分の学科名（この「学科＋学年」だけがサイトに表示されます） |
| `author.grade` | 自分の学年（1〜5） |
| `author.github` | 自分の GitHub アカウント名。**サイトには表示されません**（コメントの通知などの内部連携用） |
| `category` | 次の5つから1つ: お知らせ / 授業・教科解説 / 大学数学入門 / 競技数学・入試問題 / 活動報告 |
| `tags` | 0〜5個。新しいタグを作る前に、既存の記事で使われているタグを優先してください |
| `draft` | 下書きの間は `true`、公開時に `false`。`true` の記事は本番サイトに表示されません |
| `description` | 一覧に出る1〜2文の要約 |

### 本文を書く

- 見出しは `##`（h2）から使ってください。目次は自動で作られます
- 数式: インラインは `$x^2$`、ブロックは `$$` で囲みます（例はテンプレート内にあります）
- 画像: `public/img/articles/` に置き、本文からは `/img/articles/<ファイル名>` と絶対パスで参照してください。大きな写真は横幅 1600px 程度に縮小してから置いてください
- 著者名や個人が特定される情報は本文にも書かないでください（公開される著者情報は学科と学年だけ、という決まりです）

### お知らせ・活動報告を書く場合

- お知らせはカテゴリ「お知らせ」にすると、トップページのお知らせ欄にも自動で載ります
- 活動報告はカテゴリ「活動報告」にし、タグにイベント名などを入れてください

## 3. 手元で確認する

```bash
npm ci
npm run dev   # http://localhost:4321/ で確認
```

- `draft: true` の記事は開発サーバーでは表示されますが、本番ビルドには含まれません
- 数式や目次が崩れていないか、記事ページを開いて確認してください

## 4. PR を出す

- PR のタイトルは `content: <記事タイトル>` の形にします
- 本文には、記事の概要と、確認してほしい点（計算の正しさ等）があれば書いてください
- CI（lint + build）が通ることを確認してください。落ちた場合はエラーメッセージを見て front-matter の書き方を疑ってください

## 5. レビューの流れ（当面の運用）

- 公開前に、**最低1名の部員によるレビューと承認（Approve）を必須**とします（数学的内容の誤りのチェックのため）
- レビュアーは、誤字脱字だけでなく、計算や主張の正しさも確認してください
- 承認が付いたら、PR の作成者または承認者がマージします。マージで自動的にサイトへ公開されます

> このレビューの流れは当面の運用です（仕様書 §9-3 の未決定事項に対する暫定決定）。部の合意で変わったら、このガイドと仕様書 §12 を更新してください。

## よくあるつまずき

- **ビルドエラーになる**: front-matter のカテゴリが5分類以外になっていないか、日付の形式がずれていないかを確認してください
- **記事が一覧に出ない**: `draft: true` のままになっていないか確認してください
- **数式がそのまま表示される**: `$` の前後に余分な空白が入っていると数式として認識されません
