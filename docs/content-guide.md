# コンテンツ更新ガイド

コードを書かずにサイトを更新する手順です。データ形式の詳細は
[data-schema.md](data-schema.md) を参照してください。

## 更新の流れ

1. 対象の JSON（`public/*.json`）を編集する（GitHub の Web 画面からでも可）
2. 変更はブランチ＋PR で入れる（main への直接 push はしません）
3. PR のプレビュー代わりに、手元で `npm run dev` を起動して表示を確認する
4. マージされると自動で公開されます

自信がない場合は、Issue の「コンテンツ追加・修正依頼」テンプレートから
依頼してください。素材（文章・画像）を添付してもらえれば、担当が代わりに反映します。

## よくある更新

### お知らせを出す — `public/news.json`

配列の先頭に `{ "date": "YYYY-MM-DD", "text": "本文" }` を追加します。
トップページには最新3件だけが表示されます。

### 活動報告を足す — `public/activities.json`

[data-schema.md](data-schema.md) の形式で項目を追加します。
画像は `public/img/Activities/` に置き、名前は `YYYY-MM-DD-連番.jpg`
（例: `2025-05-11-1.jpg`）にしてください。表示は最大3枚までです。

### 過去問解説を足す — `public/exams.json` と PDF

1. PDF を `public/docs/exams/` に置く（名前は年度規則に従う）
2. `exams.json` に `{ "name": "…", "pdfUrl": "./docs/exams/….pdf" }` を追加する

### 雑記を書く — `public/notes.json`

`{ "date": "YYYY-MM-DD", "content": "本文", "author": "名前" }` を追加します。
雑記帳ページのカレンダーで、その日付を選ぶと表示されます。

## 画像についての約束事

- 表示サイズに対して大きすぎる写真（4000px級）は、そのまま置かないでください。
  横幅1600px程度へのリサイズを推奨します（Issue #14 で全体最適化を検討中）。
- ファイル名は内容や日付が分かるものにしてください（例: `aaa.jpg` のような名前は避ける）。
- 同じ写真を複数箇所で使い回さないでください（Issue #7）。
