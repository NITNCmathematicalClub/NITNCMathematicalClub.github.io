## 1. 背景と目的

- 現在、部員の発信機会は部誌のみであり、印刷の負担も小さくない。
- 授業に関係する内容や、より進んだ内容について、部員が簡単な記事を書いて公開できる環境を公式サイト上に整備する。
- 参考サービス: Qiita（技術情報の共有）、Mathlog（数学特化の記事共有）。

### ゴール
1. 部員が Markdown で記事を書き、公開までの手順が部員全員に再現可能であること。
2. 読者（部員・学校関係者・外部）が記事を分野別にたどって読めること。
3. 追加の運用費ゼロ（静的ホスティングの範囲）で継続できること。

### 非ゴール（初期段階ではやらない）
- サイト上でのユーザー登録・ログイン機能の自前実装
- いいね数やPVによるランキング
- 印刷部誌の完全な置き換え（部誌との関係は §9 の確認事項）

## 4. 方式比較：記事の追加・公開方法

> **決定（2026-10-27）: 本節の B（Astro へ移行し、§12 の徹底版で実施する）を採用する。** 以下は検討経緯の記録として残す。

静的サイトで「記事を追加する」方法は大きく4つある。

### A. Markdown ファイルをリポジトリで管理（Git/PR方式）
- 記事は `content/articles/*.md`（front-matter付き）を追加し、PR → レビュー → マージで公開。ビルド時に取り込み、一覧・詳細ページを生成する。
- 長所：費用ゼロ／既存の運用（PRレビュー文化）と一致／記事データがリポジトリに残り将来の移行も容易／改ざん・消失リスクが低い。
- 短所：Git に不慣れな部員には最初のハードルがある（→ GitHub の Web 画面だけで完結する手順書とテンプレートで緩和する）。

### B. 静的サイトジェネレータ（Astro）へ移行
- 記事の静的生成・目次・検索などが公式の仕組みで揃い、記事数が増えたときに最も堅牢。
- 長所：記事ページが完全な静的HTMLになり、表示速度・SEO・404問題すべてで有利。SPA の 404 リダイレクト（#25）のような回避策自体が不要になる。
- 短所：サイト全体の作り替えコスト。ただし現行サイトの実測は ページ8・コンポーネント9・コンテンツ4 で合計約1,700行と小さく、移行は現実的な規模（§12.1）。
- 対話的コンポーネント（HeroSlider、NoteCalendar、円グラフ等）は Astro の Islands 機能で React のまま再利用できるため、資産を全て捨てる必要はない。
- 判断：ユーザーの意向を受け、**B を採る場合は §12 の「徹底版」（全ページの Markdown 化、Figma でのデザイン先行、バージョン・Issue 整理を含む）で実施する**。

### C. ヘッドレスCMS（microCMS等）
- ブラウザの管理画面から記事を書け、サイトは API から取得して表示する。
- 長所：非エンジニアでも書きやすい／下書き・予約投稿が標準機能。
- 短所：外部サービス依存（無料枠の上限、アカウント管理）、APIキー管理、障害時の切り分け。静的サイトの「全部GitHubで完結する」良さが薄れる。

### D. 外部プラットフォームに書き、サイトは導線のみ
- Mathlog / Qiita / Zenn / note 等に部として投稿し、公式サイトには記事一覧リンク集を置く。
- 長所：開発ほぼゼロで、数式・コメント・いいねが最初から揃う。Mathlog は数学コミュニティへの露出も期待できる。
- 短所：記事資産が外部に分散し、デザインや公開可否のコントロールが弱い。部の公式サイトとしての蓄積にならない。

→ **決定: B（Astro 移行・§12 の徹底版）を採用する**（2026-10-27）。A・C は不採用。D は採用しないが、記事を外部（Mathlog 等）へ転載すること自体は妨げない。

### 4.5 A と B の詳細比較（実測ベース）

現行サイトの実測（2026-10-27、PR #28 マージ後の main）：ページ8（Home/Introduce/Activities/Exams/Note/ClubMagazine/Contact/NotFound）、コンポーネント9、コンテンツ4、合計約1,700行。対話的要素は HeroSlider、Navbar（モバイルメニュー）、NoteCalendar、PieChartByGakka（recharts）、TableOfContents（スクロール連動）の5つ程度。

| 観点 | A. 現行SPA + Markdown | B. Astro 移行 |
|---|---|---|
| 記事の書き方 | Markdown + PR（同じ） | Markdown + PR（同じ） |
| 記事ページの実体 | JS で描画（HTMLは空） | ビルド時に静的HTML生成 |
| 直接URL・404 | #25 のリダイレクト方式に依存 | 実ファイルがあるため自然に解決 |
| 表示速度 | JS バンドル読込が前提（現行 約918KB） | ページごとに必要最小限のJSのみ |
| SEO・OGP・SNS共有 | SPA のため弱い（全ページ共通の meta） | 記事ごとに meta/OGP を出し分け可能 |
| 数式（KaTeX） | ランタイム描画 | ビルド時描画も可能（高速） |
| 検索 | 自前実装（Fuse.js等） | Pagefind 等の静的検索が定番で組み込みやすい |
| 目次 | TableOfContents を流用 | Markdown 見出しから自動生成が標準 |
| 既存ページの Markdown 化 | ページ本文は JSX のまま（記事だけ MD） | 全ページ MD/MDX 化が自然にできる |
| 移行コスト | 小（記事機能の追加のみ） | 中（土台の作り替え＋全ページ移行。ただし総量約1,700行と小規模） |
| 学習コスト | ほぼなし | .astro 記法の学習が必要（HTML に近く、React 資産は Islands で再利用可） |
| デプロイ | 現行ワークフローのまま | ビルド成果物が dist の静的ファイルになるだけで、GitHub Pages + Actions の枠組みは不変 |
| 将来の拡張 | 記事が増えるとバンドル・描画が重くなる | 記事数に強く、RSS・サイトマップも標準的 |

## 5. コメント機能の検討

静的サイトにコメント欄を付ける現実的な選択肢：

| 方式 | 仕組み | 長所 | 短所 |
|---|---|---|---|
| giscus | GitHub Discussions をコメント置き場にするウィジェット | 無料・広告なし・記事とコメント対応付けが自動 | コメントには GitHub アカウントが必須 |
| utterances | GitHub Issues 版 | 同上 | 同上。Discussions 版の giscus の方が新しい |
| Disqus 等の外部サービス | 埋め込みスクリプト | アカウント不要の投稿も可 | 広告・トラッキング、デザインの不一致 |
| 付けない | — | 最も単純。感想は Discord / X 等で受け付ける運用に寄せる | サイト上で議論が完結しない |

- 読者層（高専生・中学生・一般）に GitHub アカウントを期待できるかは疑問があり、初期リリースには含めず、Phase 5 で giscus を試験導入する（Issue #38）。
- giscus を使う場合、コメントは記事に対応する GitHub Discussion に付く。**コメントが付いたことは、記事の著者の GitHub アカウントへ通知が届くようにする**（著者と GitHub アカウントの連携は §7 の著者仕様による）。

## 6. 数式表示

数学の記事では数式が中核になるため、必須機能とする。

- 方式：Markdown 処理に remark-math + rehype-katex を組み込み、KaTeX で描画する。
- KaTeX は MathJax より高速で、ビルド時・表示時どちらでも安定。対応記法は LaTeX の実用範囲をほぼカバー。
- CSS とフォントの追加でバンドルは増えるため、記事ページでのみ遅延読み込みする。
- 書き方：インライン `$...$`、ブロック `$$...$$`（Qiita / Mathlog と同じ慣習）。

## 7. タグ・検索

### タグ（記事の分類。複数指定可）

記事の分類はカテゴリではなく、front-matter の `tags` で行う（決定、2026-10-29。Issue #47）。
数学記事のタグは、分野ベースの固定25種から slug で選ぶ。定義は `src/content/tags.ts` が正本で、
定義外の slug を書くとビルドエラーになる。1記事に複数付けられ、一覧の絞り込み（チップと
タグ別ページ `/articles/tag/<slug>`）・記事カードや詳細のラベル表示・関連記事の選定に使う。

- 数学（8）: 情報（information）、計算理論（theory-of-computation）、プログラミング（programming）、代数（algebra）、幾何（geometry）、解析（analysis）、確率/統計（probability-and-statistics）、集合/論理（set-theory-and-logic）
- 物理（10）: 力学（mechanics）、電磁気学（electromagnetism）、熱力学（thermodynamics）、統計力学（statistical-mechanics）、量子力学（quantum-mechanics）、相対性理論（relativity）、波動（waves）、光学（optics）、流体力学（fluid-mechanics）、物性物理学（condensed-matter-physics）
- 化学（7）: 無機化学（inorganic-chemistry）、有機化学（organic-chemistry）、物理化学（physical-chemistry）、分析化学（analytical-chemistry）、生物化学（biochemistry）、化学工学（chemical-engineering）、高分子化学（polymer-chemistry）

お知らせ・活動報告の `tags` は従来どおり自由な文字列とし、カードや詳細では種別ラベルの
代わりにタグを表示する（タグがなければ何も表示しない）。

### 検索
- 初期：タイトル・タグ・著者を対象にしたクライアントサイド検索（Fuse.js 等の軽量ライブラリ、または単純な部分一致）で十分。
- 記事数が増えたら（目安50本超）Pagefind 等の静的検索インデックス方式へ移行を検討。

### 記事メタデータ（front-matter 仕様）
```yaml
---
title: 記事タイトル
date: 2026-11-01 # 公開日（YYYY-MM-DD、既存JSONと同じ形式）
author:
  department: 学科名 # 著者の学科
  grade: 3 # 著者の学年（1〜5）
  github: アカウント名 # 内部連携用。サイトには表示しない（下記の著者仕様を参照）
tags: [analysis] # 数学記事は定義済みタグの slug（複数可）。お知らせ・活動報告は自由記述
draft: false # true の間は本番に表示しない
description: 一覧に出す1〜2文の要約
---
```

### 著者の表示と連携（決定、2026-10-28）

- **公開表示は「学科＋学年」のみ**とする（表示形式: 「学科名 学年」の形。例: ○○学科 3年）。氏名・ハンドルネーム・GitHub アカウントは、サイト上には一切表示しない。
- **内部的には GitHub アカウントを連携させる。** front-matter の `author.github` に著者の GitHub アカウントを保持するが、これはビルド後の公開ページに出力しない。
- **コメントは著者の GitHub アカウント宛に届くようにする。** コメント機能（giscus、§5）で記事にコメントが付いた際、その記事に対応する Discussion を通じて著者が通知を受け取れるようにする。
- 考え方: サイトの外側から見える著者情報は学科と学年だけで、個人の特定にはつながらない。そのため、この範囲の公開であれば問題ないという判断による。

## 12. B案・徹底版の実施計画

ユーザーの意向（2026-10-27）：やるのであれば徹底的に行う。全ページの Markdown 化、バージョンと Project・Issue の整理、Figma で先にデザインを作ってからの実装まで含める。

### 12.8 デザインの具体像（2026-10-27 提示）

- 大本のデザインは、企業の公式サイトのような汎用的で尖りすぎないものとする。一つのイベント用の、デザイン性に寄せたものにはしない。
- ホームページの構成:
  1. 冒頭に大きく「数理同好会」と示す（参考: 工大祭 https://koudaisai.jp/ 、五月祭 https://visitor.gogatsusai.jp/ ）
  2. 次に「お知らせ」。お知らせも記事形式とし、ホームにはタイトルと短い説明のみを載せ、詳細は記事ページへ誘導する
  3. 次に、最近追加された記事などのトピックス（参考: 任天堂 https://www.nintendo.com/jp/index.html 、ノーベル賞 https://www.nobelprize.org/ ）
  4. 次に、数文程度の説明を加えたうえで、各コンテンツ（詳しい概要、記事一覧、連絡先など）へアクセスできる導線を置く
- 記事ページは manabitimes.jp / qiita.com / mathlog.info のフォーマットを基本とする。デザインの統一感のために多少の修正は行うが、フォーマット自体は変えない。
- Figma の土台には Untitled UI（無料版）を候補とする（企業の公式サイト的な、無難なデザインシステムであるため）。

### 12.9 デザイン要件（2026-10-28 壁打ちで決定）

デザインは Figma で進めるが、操作は Muse が行い、要望は壁打ちで決める進め方とする（Figma ファイルは後からユーザー側で手直しできる）。

**ホーム画面（最初の画面）**

- 「数理同好会」を大きく示すヒーローの参考: 五月祭 来場者向けサイト（https://visitor.gogatsusai.jp/ ）、工大祭（https://koudaisai.jp/ ）

**全体の雰囲気**

- 参考: 任天堂（https://www.nintendo.com/jp/ ）、ノーベル賞（https://www.nobelprize.org/ ）、Apple（https://www.apple.com/jp/ ）。色そのものではなく、全体の雰囲気を参考にする
- フラットなデザインとする。影でパーツを分けることはせず、立体感のある表現も基本的には付けない。区切りは色の帯と余白で作る

**色**

- ベースは現行サイトの紺（#27455C）を継承し、アクセントにゴールド（#CEA152）を使う
- ライトモードの地は、完全な白ではなく少し調整した白とする（トークンでは #FAF9F6 を採用）
- ダークモードは紺をベースにし、暗い環境で違和感がないよう調整する（地は #101D27、帯は #1B3245、ゴールドは明るくした #D9B877）

**タイポグラフィ**

- 見出し（ヒーロー・ページタイトル）は Noto Serif JP、本文は Noto Sans JP とする（現行サイトの明朝見出しの伝統を引き継ぐ）※ 見出しはその後の比較の結果、§12.10 のとおり Noto Sans JP（ゴシック）に変更して確定した

**Figma 運用上の制約**

- ファイル: 「数理同好会 公式サイト v2.0.0 デザイン」（URL は Issue #31 に記録）
- Starter プランのため、ページは3ページまで（カバー／トークン＆コンポーネント／テンプレート）。Variables のモードは1コレクションにつき1つまでのため、ライト用とダーク用でコレクションを分けて保持する

### 12.10 デザイン確定版（2026-10-28 確定）

Figma でテンプレートを作成し、ユーザーの確認を経て確定した。§12.9 から変更・追加された確定事項は次のとおり。Figma ファイルは Education チーム「沼津高専 数理同好会」に移され、学校アカウントで運用している（ファイルの URL は Issue #31 に記録）。

**タイポグラフィ（変更）**

- 見出しは Noto Sans JP（ゴシック）の太字に変更して確定した。ロゴ文字（ヘッダー／フッターの「数理同好会」）のみ Noto Serif JP を残す。本文は Noto Sans JP

**テンプレート（全18種：Desktop 9種＋Mobile 9種）**

- ホーム、記事一覧、記事詳細、お知らせ一覧、お知らせ詳細、活動報告一覧、活動報告詳細、静的ページ（汎用）、404（いずれも Desktop／Mobile の両方）

**ホーム**

- ヒーローは全画面（ファーストビュー全体）とし、写真を全面に置いて紺のグラデーションを重ねる（左を濃くしてタイトルを読ませる。地の色へのフェードは付けない。モバイルは文字が読めるよう紺を濃くする）。写真は差し替え可能で、当面は仮の写真で確認する
- 「数理同好会について」は紺の帯ではなく白背景とする（大きな色面はヒーローのみ）
- 「最近の記事」の背景は「お知らせ」と同じ地の色とし、カードは色ではなく罫線で区切る

**一覧ページ**

- 活動報告一覧も同じグリッドを流用し、各報告に年度タグを付ける。表示は年度セレクタで切り替え、ページ分割はしない（選択した年度の報告をすべて表示する）

**記事詳細**

- 本文は幅800の中央カラムとする。リード画像は任意で、写真は必須ではない（画像なしでも成立する構成とする）
- 目次は右レールに置く追随型とする（Nobel Prize の記事ページを参考）
- 末尾に「関連記事」（カード3件）を置く
- 数式は TeX で組版したのと同じ見た目で表示する（実装は KaTeX。文字は黒とし、背景色は付けない）
- 著者表示は §7 の決定どおり「学科＋学年」のみとする

**お知らせ詳細・活動報告詳細・静的ページ**

- いずれも記事と基礎を同じくする構成（幅800カラム、タイトル、日付・タグ、本文、見出し、情報の表）とする。記事との差は、著者表示・目次・関連記事がない程度とする

**404**

- 白背景・黒文字とする

**ヘッダー**

- 全ページ共通で、半透明＋背景ブラー（すりガラス）の固定ヘッダーとする

**デザイン確定時点の残作業**

- なし（コンポーネント化まで完了）。コンポーネント化の内容: ヘッダー（Desktop は現在地を表すバリアント「Active」を持つ）／フッター／記事カード／チップ／ページネーション／見出し／目次／リード画像をコンポーネントとしてトークンページに集約し、全テンプレートのヘッダーとフッターはそのインスタンスに置き換えた

なお、記事系のモバイル版テンプレートは確定後に追加作成済み（2026-10-28）。モバイル版の記事詳細では、目次は右レールではなく開閉式のボックスとする。Figma のテンプレートページは Desktop／Mobile の2列に整列した。

### 12.11 英字フォントの追加決定（2026-10-28）

§12.10 の確定後に検討し、ユーザーの確認を経て追加で決定した。Figma のテンプレートとコンポーネントには適用済み。

- 英数字は Noto Sans JP の欧文ではなく、専用の英字フォントを使う（和欧混植）。日本語は Noto Sans JP のまま
- 基本（日付、本文中の英数字、ラベルなどの小さい文字）は Roboto とする
- 大きな表示（28px 以上。見出し中の英数字や 404 の数字など）は Montserrat とする
- 句読点や括弧の余白を詰める処理（約物詰め）は Figma では行わず、実装時に CSS（yakuhanjp 相当、または `text-spacing-trim`）で対応する
- カラーパレットは §12.10 の現行（紺＋ゴールド）を維持する（暗色基調などの別案も比較したが、採用しなかった）
